# Rain Autoresearch UI

不用寫程式，就能幫測站降雨模型做深度學習調參的操作介面。

[線上Demo](https://x200706.github.io/rain-autoresearch-ui/)（靜態 HTML 原型）

這個倉庫有兩個版本：

| 版本 | 檔案 | 用途 |
|---|---|---|
| Gradio 介面 | `app.py`、`rainui/` | 真正的介面：在本機讀實驗紀錄、啟動 Hermes、即時顯示進度與結果 |
| HTML 原型 | `index.html`、`data/` | GitHub Pages 上的展示，不會訓練；保留給已寄出的連結使用 |

## 啟動 Gradio 介面

需要 Python 3.10 以上。

```bash
pip install -r requirements.txt
python app.py
```

開啟 <http://127.0.0.1:7860>。

介面預設讀 `../rain_autoresearch`（與本倉庫同一層的實驗專案）。其他位置與行為用環境變數調整：

| 環境變數 | 預設 | 說明 |
|---|---|---|
| `RAIN_AUTORESEARCH_ROOT` | `../rain_autoresearch` | 實驗專案根目錄（有 `program.md`、`outputs/`、`data/`） |
| `RAIN_UI_MODE` | 自動 | `real`：真的啟動 Hermes；`demo`：只播放等待動畫。自動模式在找得到 Hermes 和實驗專案時用 `real` |
| `HERMES_CMD` | 找 `hermes` | Hermes CLI 的路徑；多個參數用 `\|` 分隔 |
| `HERMES_HOME` | `~/Hermes` 或 `~/.hermes` | 介面把這次實驗的 `SKILL.md` 寫到 `<HERMES_HOME>/skills/research/<技能名稱>/` |
| `RAIN_UI_STATE_DIR` | `./runs` | 介面自己的紀錄：實驗名稱、備註、Hermes 輸出 |
| `GRADIO_SERVER_PORT` | `7860` | 連接埠 |

找不到實驗專案時（例如在別台電腦上），介面改讀 `data/experiments.js` 的五站資料，只能瀏覽與播放展示動畫。

實驗專案路徑也可以在介面左側「2 · 實驗與測站資料」直接修改；找不到 `program.md` 時會顯示錯誤，不會切換。

## 介面做什麼

左欄最上方切換「訓練與評估」與「線上預測」。

### 訓練與評估

1. **左欄收集設定**：OpenRouter Key 與代理模型（清單即時從 OpenRouter 抓，預設 `deepseek/deepseek-v4.1-flash-1017`）、實驗名稱、測站資料（已有資料的測站、從中興大學資料庫下載，或上傳 CSV）、切分、主目標、副目標、演化參數。欄位格式不對時，錯誤直接顯示在該欄位下方，並擋住開始按鈕。
2. **產生技能**：把設定填進模板的 `[[欄位]]`，在「6 · 預覽」可以看與修改。主目標或副目標和預設（≥ 40 mm 的 MAE、三種副目標）不同時，技能最前面會加一節「介面覆寫（優先級最高）」，要求 Hermes 先修改 `budget_guard.py` 與 `program.md`、跑過測試，再開始實驗。
3. **設定快取**：設定和已完成的實驗完全相同時，按鈕變成「Cache Hit・展示快取結果」，直接顯示結果。
4. **啟動 Hermes**：
   ```bash
   hermes chat --provider openrouter -m <模型> -s <技能名稱> --yolo -Q --format stream-json \
     --in <實驗專案> --query-file prompt.txt [--api-key <Key>]
   ```
   API Key 只在這次啟動時傳給 Hermes，不寫進任何檔案；留空則用電腦中 Hermes 預設的 OpenRouter Key。
5. **等待動畫**：把論文圖 3.4 簡化成七個步驟，依 `outputs/<站號>/` 的檔案判斷目前走到哪一步；代理迴圈中會標出目前的副目標、代數，以及正在產生子代、訓練或評估。
6. **結果自動更新**：每 3 秒檢查一次。學習紀錄與消融比較表在這次實驗開始後出現，就算完成，主畫面自動換成結果：數字卡、收斂圖、可縮放的訓練集與測試集預測圖（跟著各副目標的最佳基因）、`results.tsv`、測站資訊卡、學習紀錄、消融比較。
7. **備註**：實驗結束後可以在主畫面下方寫備註，存在 `runs/`，不動 `outputs/` 的實驗紀錄。
8. **刪除實驗**：按主畫面右上角的「刪除實驗」，頁面上會先出現紅色確認列，按「確定刪除」才會刪除，無法復原。介面啟動的實驗刪的是介面的紀錄（名稱、備註、Hermes 輸出）；已完成的測站刪的是整個 `outputs/<站號>`。

   **中興大學資料庫**：先選站種（有人站、自動氣象站、自動雨量站、農業站，清單取自氣象署[現存測站表](https://hdps.cwa.gov.tw/static/state.html)，連不上時用 `data/cwa_stations.csv`），再選測站，按「從中興大學下載 2009 年至今」。一次抓 2009-01-01 到今天，約 2–3 分鐘；中興沒有這個站的資料就會顯示「這個測站不能用」。下載的檔案存在 `runs/nchu/`，開始實驗時才複製到實驗專案的 `data/<站號>.csv`（已有不同內容的檔案時不覆寫）。

### 線上預測

選測站與時間 T，按「預測這一小時」：當場抓 T 之前的逐時觀測，照訓練時的前處理組成特徵，第一階段雙 LightGBM 判斷 T 有沒有雨，判定有雨才由 LSTM 估雨量。資料不存檔。畫面顯示 T 的預測、同時段觀測（有的話）、前 23 小時的預測對照，以及每個輸入欄位這段時間有沒有值。

資料來源：

- **到昨天 24 時**：氣象署 [CoDiS](https://codis.cwa.gov.tw/)，不需要金鑰，欄位最齊。CoDiS 網站本身也只能選到前一天。
- **今天的整點**：氣象署開放資料 `O-A0001-001`（每 10 分鐘更新），今天稍早的整點用「短期過去資料下載」API 取回。需要授權碼：預測分頁第一欄輸入，到[氣象資料開放平臺](https://opendata.cwa.gov.tw/user/authkey)免費註冊後複製。授權碼不存檔；即時資料放在 HTTP header，短期過去資料 API 只收網址參數，錯誤訊息不會帶出授權碼。短期過去資料只留過去 24 小時的整點快照（每份是全台測站的 XML，約 1.7 MB），一次預測約下載 20 份、十幾秒。以 2026-11-16 20–24 時實測，和 CoDiS 重疊的整點氣溫、溼度、測站氣壓、風速、雨量逐筆相同，風向只到 10 度。這個資料集只有氣溫、溼度、測站氣壓、風、陣風與當日累積雨量；逐時雨量由相鄰整點相減，露點由氣溫與溼度算出，其他欄位沿用 CoDiS 昨天最後一筆。
- 沒有授權碼時最晚只能預測今天 01 時。

其他說明：

- 往前抓「較佳化搜尋最長的序列（24 小時）＋ 一天」，換成搜尋空間內任何模型都夠用。
- 目前打包的是鞍部（466910）副目標「AE ≥ 20 mm 低估筆數」的最佳基因 g04_c1。

模型放在 `deploy/<站號>/`，在有實驗紀錄的電腦上打包：

```bash
python tools/export_model.py D:/rain_autoresearch 466910 --subgoal under
```

打包時會用同一套前處理重算整段測試集，和實驗輸出的 `test_two_stage_predictions.csv` 比對（鞍部 26,302 小時：gate 判定 0 筆不同、雨量最大差 0.0000 mm），不一致就不寫出。線上補值只能用抓到的這一小段（訓練時測試期是整段插值，會用到之後的觀測），以 2025 年 6 月逐日線上重算，720 小時中有 1 小時的有無雨判定與測試集不同。
